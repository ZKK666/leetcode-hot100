# 169. 多数元素【简单】

## 题目描述

给定一个大小为 `n` 的数组 `nums`，返回其中的多数元素。多数元素是指在数组中出现次数**大于** `⌊n/2⌋` 的元素。

你可以假设数组是非空的，并且给定的数组总是存在多数元素。

---

## 输入输出示例

### 示例 1
```
输入：nums = [3,2,3]
输出：3
```

### 示例 2
```
输入：nums = [2,2,1,1,1,2,2]
输出：2
```

### 提示
- `n == nums.length`
- `1 <= n <= 5 * 10^4`
- `-10^9 <= nums[i] <= 10^9`

**进阶：** 尝试设计时间复杂度为 O(n)、空间复杂度为 O(1) 的算法解决此问题。

---

## 解题思路（面试推荐 - 最优解）

### 核心思想

**问题特点：**
```
多数元素：出现次数 > ⌊n/2⌋

关键性质：
多数元素一定超过数组长度的一半
这意味着：
- 排序后，中间元素一定是多数元素
- 多数元素的个数 > 其他所有元素个数之和
```

**多种解法：**
```
1. 哈希表：O(n) 时间，O(n) 空间
2. 排序：O(nlogn) 时间，O(1) 空间
3. Boyer-Moore投票算法：O(n) 时间，O(1) 空间 ⭐
```

---

### 方法一：Boyer-Moore 投票算法（推荐）

**核心思想：**
- 候选人 vs 其他所有人
- 多数元素的个数 > 其他元素个数之和
- 配对抵消后，剩下的一定是多数元素

**算法流程：**

1. **初始化：**
   - candidate（候选人）
   - count（计数器）= 0

2. **遍历数组：**
   - 如果 count == 0：
     - candidate = 当前元素
     - count = 1
   - 否则：
     - 如果当前元素 == candidate：count++
     - 如果当前元素 != candidate：count--

3. **返回 candidate**

**为什么有效？**
```
多数元素个数 > n/2
其他元素个数 < n/2

配对抵消：
- 多数元素 vs 非多数元素：抵消
- 抵消后，多数元素还有剩余

最后剩下的一定是多数元素
```

**时间复杂度：** O(n)
**空间复杂度：** O(1)

---

### 方法二：排序

**核心思想：**
- 排序后，中间位置的元素一定是多数元素

**为什么？**
```
多数元素个数 > n/2

无论多数元素如何分布：
排序后必然占据中间位置

例如：n=7，多数元素至少4个
[x x x x _ _ _]  中间是x
[_ x x x x _ _]  中间是x
[_ _ x x x x _]  中间是x
[_ _ _ x x x x]  中间是x
```

**时间复杂度：** O(nlogn)
**空间复杂度：** O(1) 或 O(n)（取决于排序算法）

## 代码实现（TypeScript）

### 方法一：Boyer-Moore 投票算法（推荐，最优解）

```typescript
function majorityElement(nums: number[]): number {
    let candidate = 0;
    let count = 0;

    for (const num of nums) {
        if (count === 0) {
            // 选举新的候选人
            candidate = num;
            count = 1;
        } else if (num === candidate) {
            // 支持当前候选人
            count++;
        } else {
            // 反对当前候选人
            count--;
        }
    }

    // 题目保证一定存在多数元素，直接返回
    return candidate;
}
```

**验证版本（如果不保证存在多数元素）：**

```typescript
function majorityElement(nums: number[]): number {
    let candidate = 0;
    let count = 0;

    // 第一轮：找出候选人
    for (const num of nums) {
        if (count === 0) {
            candidate = num;
        }
        count += (num === candidate) ? 1 : -1;
    }

    // 第二轮：验证候选人是否是多数元素
    count = 0;
    for (const num of nums) {
        if (num === candidate) {
            count++;
        }
    }

    if (count > Math.floor(nums.length / 2)) {
        return candidate;
    }

    return -1; // 不存在多数元素
}
```

### 方法三：哈希表

```typescript
function majorityElement(nums: number[]): number {
    const count = new Map<number, number>();
    const n = nums.length;

    for (const num of nums) {
        count.set(num, (count.get(num) || 0) + 1);

        // 找到超过n/2的元素
        if (count.get(num)! > Math.floor(n / 2)) {
            return num;
        }
    }

    return -1; // 不会到达
}
```

**时间复杂度：** O(n)
**空间复杂度：** O(n)

### 方法四：分治法

```typescript
function majorityElement(nums: number[]): number {
    return majorityElementRec(nums, 0, nums.length - 1);
}

function majorityElementRec(nums: number[], left: number, right: number): number {
    // 基本情况
    if (left === right) {
        return nums[left];
    }

    // 分治
    const mid = Math.floor((left + right) / 2);
    const leftMajor = majorityElementRec(nums, left, mid);
    const rightMajor = majorityElementRec(nums, mid + 1, right);

    // 如果两边相同
    if (leftMajor === rightMajor) {
        return leftMajor;
    }

    // 统计两个候选者在整个区间的出现次数
    const leftCount = countInRange(nums, leftMajor, left, right);
    const rightCount = countInRange(nums, rightMajor, left, right);

    return leftCount > rightCount ? leftMajor : rightMajor;
}

function countInRange(nums: number[], target: number, left: number, right: number): number {
    let count = 0;
    for (let i = left; i <= right; i++) {
        if (nums[i] === target) {
            count++;
        }
    }
    return count;
}
```

**时间复杂度：** O(nlogn)
**空间复杂度：** O(logn)（递归栈）

## 代码原理详解

### Boyer-Moore 投票算法

**1. 为什么配对抵消有效？**

```
假设数组：[2, 2, 1, 1, 1, 2, 2]

多数元素2出现4次
其他元素1出现3次

配对抵消：
2 vs 1：抵消1对
2 vs 1：抵消1对
2 vs 1：抵消1对

剩余：2（还有1个）

无论如何抵消，多数元素总会剩余
```

**2. 执行过程详解：**

```
数组：[2, 2, 1, 1, 1, 2, 2]

初始：candidate = 0, count = 0

i=0, num=2：
  count == 0 → candidate = 2, count = 1

i=1, num=2：
  num == candidate → count = 2

i=2, num=1：
  num != candidate → count = 1（抵消）

i=3, num=1：
  num != candidate → count = 0（抵消）

i=4, num=1：
  count == 0 → candidate = 1, count = 1（换候选人）

i=5, num=2：
  num != candidate → count = 0（抵消）

i=6, num=2：
  count == 0 → candidate = 2, count = 1

返回：2 ✓
```

**3. 为什么count=0时换候选人？**

```
count = 0 意味着：
当前候选人被完全抵消了

重新选举：
选当前元素作为新候选人

这不影响最终结果：
因为多数元素个数 > n/2
无论如何换候选人，最后剩下的一定是多数元素
```

**4. 类比：投票选举**

```
想象一场选举：
- 多数派候选人票数 > 50%
- 其他所有候选人票数 < 50%

配对抵消过程：
每遇到一个反对票，抵消一个支持票

最后：
多数派候选人一定还有剩余票数
```

---

### 排序方法

**为什么中间元素一定是多数元素？**

```
设数组长度为n，多数元素个数为k

条件：k > n/2

排序后：
多数元素必然占据中间位置 nums[n/2]

证明：
假设多数元素不在中间位置

情况1：全部在左半边
最多占据位置 [0, n/2-1]
个数最多 n/2 < k（矛盾）

情况2：全部在右半边
最多占据位置 [n/2+1, n-1]
个数最多 n/2 < k（矛盾）

因此：
多数元素必然跨越中间位置
nums[n/2] 一定是多数元素
```

## 常见问题

**Q1: 为什么投票算法有效？**
A: 多数元素的性质：
```
多数元素个数 > n/2
其他所有元素个数 < n/2

配对抵消：
多数元素 vs 其他元素
抵消后多数元素还有剩余

最后剩下的一定是多数元素
```

**Q2: 如果不存在多数元素怎么办？**
A: 需要验证：
```
投票算法只保证找到候选人
不保证候选人是多数元素

需要第二轮遍历验证：
统计候选人出现次数
判断是否 > n/2
```

**Q3: 为什么题目保证存在多数元素就不需要验证？**
A: 数学保证：
```
如果存在多数元素：
投票算法一定找到它

如果不存在：
投票算法可能返回任意元素

题目保证存在 → 可以直接返回
```

**Q4: 排序方法为什么取中间位置？**
A: 多数元素的性质：
```
个数 > n/2

排序后：
无论多数元素如何分布
必然占据中间位置 nums[n/2]
```

**Q5: 如果要求找出现次数 > n/3 的元素呢？**
A: Boyer-Moore的扩展：
```
题目：229. 求众数 II

最多有2个元素满足条件
需要维护2个候选人

投票算法变体：
同时维护candidate1和candidate2
```
