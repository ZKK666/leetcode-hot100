# 128. 最长连续序列【中等】

## 题目描述

给定一个未排序的整数数组 `nums`，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

请你设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

---

## 输入输出示例

### 示例 1
```
输入：nums = [100,4,200,1,3,2]
输出：4
解释：最长数字连续序列是 [1, 2, 3, 4]。它的长度为 4。
```

### 示例 2
```
输入：nums = [0,3,7,2,5,8,4,6,0,1]
输出：9
解释：最长数字连续序列是 [0,1,2,3,4,5,6,7,8]。它的长度为 9。
```

### 提示
- `0 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

---

## 解题思路（面试推荐 - 最优解）

### 方法：哈希集合（HashSet）

**核心思想：**
- 使用 HashSet 存储所有数字，实现 O(1) 的查找
- 关键优化：只从连续序列的**起点**开始计数
- 如果 `num - 1` 存在于集合中，说明 `num` 不是起点，跳过
- 如果 `num - 1` 不存在，说明 `num` 是起点，开始向后查找 `num+1, num+2, ...`
- 记录所有序列中的最大长度

**为什么能达到 O(n)？**
- 虽然有两层循环，但每个数字最多被访问 2 次：
  - 第一次：作为外层循环的当前元素
  - 第二次：作为某个序列的一部分被内层循环访问
- 因为只从起点开始计数，避免了重复计算

**举例说明：**
```
nums = [100, 4, 200, 1, 3, 2]

set = {100, 4, 200, 1, 3, 2}

遍历100: 99不在set中 → 100是起点 → 查找101不在 → 长度1
遍历4:   3在set中   → 4不是起点 → 跳过
遍历200: 199不在set中 → 200是起点 → 查找201不在 → 长度1
遍历1:   0不在set中 → 1是起点 → 查找2,3,4都在 → 长度4 ✓
遍历3:   2在set中   → 3不是起点 → 跳过
遍历2:   1在set中   → 2不是起点 → 跳过
```

**时间复杂度：** O(n) - 每个元素最多访问常数次
**空间复杂度：** O(n) - HashSet 存储所有元素

## 代码实现（TypeScript）

```typescript
function longestConsecutive(nums: number[]): number {
    // 边界情况：空数组直接返回0
    if (nums.length === 0) return 0;

    // 将所有数字存入HashSet，用于O(1)时间查找
    const numSet = new Set<number>(nums);

    // 记录最长连续序列的长度
    let maxLength = 0;

    // 遍历集合中的每个数字
    for (const num of numSet) {
        // 关键优化：只从序列的起点开始计数
        // 如果num-1存在，说明num不是起点，跳过
        if (numSet.has(num - 1)) {
            continue;
        }

        // 执行到这里说明num是某个连续序列的起点
        let currentNum = num;
        let currentLength = 1;

        // 向后查找连续的数字：num+1, num+2, num+3, ...
        while (numSet.has(currentNum + 1)) {
            currentNum++;
            currentLength++;
        }

        // 更新最大长度
        maxLength = Math.max(maxLength, currentLength);
    }

    return maxLength;
}
```

## 代码原理详解

### 核心逻辑

1. **构建 HashSet**：
   - `new Set<number>(nums)` 自动去重并提供 O(1) 查找
   - 避免了排序的 O(n log n) 时间复杂度

2. **识别序列起点**：
   - 通过 `numSet.has(num - 1)` 判断当前数字是否是起点
   - 如果 `num - 1` 存在，说明还有更小的数，当前数不是起点
   - 只有起点才开始向后计数，避免重复计算

3. **向后扩展**：
   - 从起点开始，不断查找 `currentNum + 1` 是否存在
   - 每找到一个就将长度 +1，并更新 currentNum
   - 直到找不到为止

4. **更新最大值**：
   - 每找到一个完整序列，就与当前最大长度比较

### 设计思路

- **去重优化**：HashSet 自动去重，避免重复元素干扰
- **起点识别**：通过检查 `num - 1` 是否存在，巧妙地识别序列起点
- **单向扩展**：只向后查找，不向前查找，每个序列只计算一次
- **时间换空间的艺术**：用 O(n) 空间换取 O(n) 时间复杂度

## 时间复杂度分析

**为什么是 O(n) 而不是 O(n²)？**

虽然代码看起来有两层循环，但实际上：

```
外层循环：遍历n个数字
内层循环：只在起点时执行

关键点：每个数字最多被内层while循环访问一次
- 如果num是起点，它会在自己的while中被访问
- 如果num不是起点，它会在某个起点的while中被访问
- 不可能被访问两次，因为序列是连续的

总访问次数 = 外层n次 + 内层最多n次 = O(2n) = O(n)
```

**举例：**
```
nums = [1, 2, 3, 4, 5]

外层循环访问：1, 2, 3, 4, 5 (5次)
内层循环访问：
  - 当num=1时：2, 3, 4, 5 (4次)
  - 当num=2,3,4,5时：跳过 (0次)

总计：5 + 4 = 9次访问 < 2n
```

## 常见问题

**Q1: 为什么不直接排序后查找连续序列？**
A: 排序的时间复杂度是 O(n log n)，不满足题目要求的 O(n)。

**Q2: HashSet 的查找真的是 O(1) 吗？**
A: 在平均情况下是 O(1)，最坏情况下可能退化到 O(n)（哈希冲突），但一般可以认为是 O(1)。

**Q3: 为什么要用 Set 而不是 Map？**
A: 我们只需要判断数字是否存在，不需要存储额外信息，所以 Set 更合适。

**Q4: 如果数组中有重复元素会怎样？**
A: Set 会自动去重，不影响结果。例如 [1, 2, 2, 3] → Set {1, 2, 3}，连续序列长度仍然是 3。
