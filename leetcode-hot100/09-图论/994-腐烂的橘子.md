# 994. 腐烂的橘子【中等】

## 题目描述

在给定的 `m x n` 网格 `grid` 中，每个单元格可以有以下三个值之一：

- 值 `0` 代表空单元格
- 值 `1` 代表新鲜橘子
- 值 `2` 代表腐烂的橘子

每分钟，腐烂的橘子 **周围 4 个方向上相邻** 的新鲜橘子都会腐烂。

返回 **直到单元格中没有新鲜橘子为止所必须经过的最小分钟数**。如果不可能，返回 `-1`。

---

## 输入输出示例

### 示例 1

![示例1](https://assets.leetcode-cn.com/aliyun-lc-upload/uploads/2019/02/16/oranges.png)

```
输入：grid = [[2,1,1],[1,1,0],[0,1,1]]
输出：4
```

### 示例 2
```
输入：grid = [[2,1,1],[0,1,1],[1,0,1]]
输出：-1
解释：左下角的橘子（第 2 行，第 0 列）永远不会腐烂，因为腐烂只会发生在 4 个方向上。
```

### 示例 3
```
输入：grid = [[0,2]]
输出：0
解释：因为 0 分钟时已经没有新鲜橘子了，所以答案就是 0。
```

### 提示
- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 10`
- `grid[i][j]` 仅为 `0`、`1` 或 `2`

## 解题思路（面试推荐 - 最优解）

### 核心思想

**问题本质：**
```
多源BFS问题

特点：
1. 多个起点（所有腐烂的橘子）同时开始扩散
2. 每一轮扩散代表1分钟
3. 求所有新鲜橘子都腐烂的最小时间

类比：
- 病毒传播
- 地图洪水填充
- 森林火灾蔓延
```

**为什么用BFS？**
```
BFS特点：
- 层序遍历，每层代表一个时间单位
- 保证找到最短时间
- 天然支持多源同时扩散

DFS不适用：
- DFS无法保证最短时间
- DFS是深度优先，不是层序
```

---

### 方法：多源BFS

**算法流程：**

1. **初始化：**
   - 统计新鲜橘子数量
   - 将所有腐烂橘子加入队列

2. **BFS扩散：**
   - 每轮处理当前队列中的所有橘子
   - 腐烂四个方向的新鲜橘子
   - 新腐烂的橘子加入队列
   - 时间+1

3. **结束判断：**
   - 如果还有新鲜橘子，返回-1
   - 否则返回经过的时间

**关键点：**
```
多源BFS = 所有起点同时加入队列

例如：
初始：
2 1 1
1 1 0
0 1 2

队列：[(0,0), (2,2)]  // 两个腐烂橘子同时开始

第1分钟：
2 2 1    队列：[(0,1), (1,0), (2,1), (1,2)]
2 1 0
0 2 2

第2分钟：
2 2 2    队列：[(0,2), (1,1)]
2 2 0
0 2 2

第3分钟：
2 2 2    队列：[(1,2)]
2 2 0
0 2 2

第4分钟：
2 2 2    队列：[]
2 2 0
0 2 2

结果：4分钟
```

**时间复杂度：** O(m×n) - 每个格子最多访问一次
**空间复杂度：** O(m×n) - 队列最大可能包含所有格子

## 代码实现（TypeScript）

```typescript
function orangesRotting(grid: number[][]): number {
    const m = grid.length;
    const n = grid[0].length;

    // 队列：存储腐烂橘子的位置
    const queue: [number, number][] = [];
    let freshCount = 0;  // 新鲜橘子数量

    // 统计新鲜橘子，收集腐烂橘子
    for (let i = 0; i < m; i++) {
        for (let j = 0; j < n; j++) {
            if (grid[i][j] === 1) {
                freshCount++;
            } else if (grid[i][j] === 2) {
                queue.push([i, j]);
            }
        }
    }

    // 特殊情况：没有新鲜橘子
    if (freshCount === 0) {
        return 0;
    }

    // 四个方向
    const directions = [[-1, 0], [1, 0], [0, -1], [0, 1]];
    let minutes = 0;

    // BFS扩散
    while (queue.length > 0 && freshCount > 0) {
        // 当前这一轮的橘子数量
        const size = queue.length;

        // 处理这一轮的所有腐烂橘子
        for (let i = 0; i < size; i++) {
            const [x, y] = queue.shift()!;

            // 尝试腐烂四个方向的橘子
            for (const [dx, dy] of directions) {
                const nx = x + dx;
                const ny = y + dy;

                // 边界检查 + 新鲜橘子检查
                if (nx >= 0 && nx < m && ny >= 0 && ny < n && grid[nx][ny] === 1) {
                    // 腐烂这个橘子
                    grid[nx][ny] = 2;
                    freshCount--;
                    queue.push([nx, ny]);
                }
            }
        }

        // 这一轮结束，时间+1
        minutes++;
    }

    // 如果还有新鲜橘子，说明无法全部腐烂
    return freshCount === 0 ? minutes : -1;
}
```

## 代码原理详解

### 核心逻辑

**1. 初始化阶段：**
```typescript

for (let i = 0; i < m; i++) {
    for (let j = 0; j < n; j++) {

            freshCount++;  // 记录新鲜橘子数量
        } else if (grid[i][j] === 2) {
            queue.push([i, j]);  // 所有腐烂橘子入队
        }
    }
}
```

**2. 分层BFS：**
```typescript
const size = queue.length;  // 当前层的大小

for (let i = 0; i < size; i++) {
    // 只处理当前层的橘子
    const [x, y] = queue.shift()!;
    // ...
}

minutes++;  // 处理完一层，时间+1
```

**3. 腐烂传播：**
```typescript
if (grid[nx][ny] === 1) {
    grid[nx][ny] = 2;      // 标记为腐烂
    freshCount--;          // 新鲜橘子数量-1
    queue.push([nx, ny]);  // 加入队列，下一轮继续扩散
}
```

## 常见问题

**Q1: 为什么是多源BFS？**
A: 所有腐烂橘子同时开始扩散：
```
单源BFS：从一个点开始
多源BFS：从多个点同时开始

实现：将所有起点一起加入初始队列
```

**Q2: 如何保证时间最短？**
A: BFS的层序特性：
```
BFS按层扩散：
- 第1层：距离起点1步
- 第2层：距离起点2步
- ...

每层处理完才进入下一层，保证最短时间
```

**Q3: 为什么需要freshCount？**
A: 判断是否有孤立橘子：
```
如果有橘子被障碍物包围：
  0 0 0
  0 1 0
  0 0 0

BFS无法到达，freshCount不为0
需要返回-1
```

**Q4: 可以用DFS吗？**
A: 不能：
```
DFS问题：
1. 无法保证最短时间
2. 需要遍历所有路径取最小值
3. 时间复杂度更高

BFS优势：
- 第一次到达即最短
- 层序遍历天然支持
```

**Q5: 为什么要记录size？**
A: 区分每一轮（每分钟）：
```
while (queue.length > 0) {
    const size = queue.length;  // 关键！

    for (let i = 0; i < size; i++) {
        // 只处理这一轮的橘子
    }

    minutes++;  // 这一轮结束
}

如果不记录size：
无法区分哪些橘子是这一轮腐烂的
时间计算会错误
```

## 复杂度分析

**时间复杂度：** O(m×n)
- 每个格子最多访问一次
- 初始化：O(m×n)
- BFS：每个橘子最多入队一次

**空间复杂度：** O(m×n)
- 队列最多包含所有格子
- 最坏情况：整个网格都是腐烂橘子

## 方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 能否保证最短 | 推荐度 |
|------|-----------|-----------|-------------|--------|
| 多源BFS | O(m×n) | O(m×n) | ✓ | ⭐⭐⭐⭐⭐ |
| DFS | O(m×n×4^(m×n)) | O(m×n) | ✗ | ⭐ |
| 模拟 | O(k×m×n) | O(1) | ✓但慢 | ⭐⭐ |

注：k是总轮数，模拟方法每轮重新扫描整个网格

## 总结

**关键点：**
1. 多源BFS：所有起点同时加入队列
2. 分层处理：记录每层大小，区分每一轮
3. freshCount判断：检查是否有孤立橘子
4. 原地修改：直接修改grid标记已访问

**面试建议：**
- 先说明这是多源BFS问题
- 解释为什么用BFS而不是DFS
- 强调分层处理的重要性（size变量）
- 说明freshCount的作用
- 画图演示扩散过程

**易错点：**
- 忘记记录队列大小（size），导致时间计算错误
- 忘记统计新鲜橘子数量
- 返回时没有检查freshCount
- 边界条件：没有新鲜橘子、没有腐烂橘子
- 将minutes初始化为1（应该是0）
