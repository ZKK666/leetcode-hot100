# 11. 盛最多水的容器【中等】

## 题目描述

给定一个长度为 `n` 的整数数组 `height`。有 `n` 条垂线，第 `i` 条线的两个端点是 `(i, 0)` 和 `(i, height[i])`。

找出其中的两条线，使得它们与 x 轴共同构成的容器可以容纳最多的水。

返回容器可以储存的最大水量。

**说明**：你不能倾斜容器。

---

输出：49

在此情况下，容器能够容纳水（表示为蓝色部分）的最大值为 49。

## 解题思路（面试推荐 - 最优解）

### 方法：双指针（对撞指针）

**核心思想：**
- 使用两个指针 `left` 和 `right`，分别指向数组的两端
- 容器的容量 = `min(height[left], height[right]) * (right - left)`
- 每次移动较矮的那一边的指针
- 为什么移动较矮的那边？因为：
  - 容量由较矮的边决定（木桶原理）
  - 移动较高的边只会让宽度变小，高度不会增加（受限于矮边）
  - 移动较矮的边，虽然宽度变小，但有可能遇到更高的边，容量可能增大

**为什么不用暴力法？**
- 暴力法需要遍历所有可能的两条线组合，时间复杂度 O(n²)
- 双指针法利用贪心思想，只需遍历一次，时间复杂度 O(n)

**正确性证明：**
```
假设 height[left] < height[right]

如果移动 right：
  - 新容量 = min(height[left], height[right-1]) * (right-1-left)
  - 因为 height[left] 是瓶颈，min(...) <= height[left]
  - 宽度减小：(right-1-left) < (right-left)
  - 所以新容量一定 <= 旧容量

如果移动 left：
  - 新容量 = min(height[left+1], height[right]) * (right-left-1)
  - 虽然宽度减小，但 height[left+1] 可能 > height[left]
  - 所以有机会得到更大的容量

结论：只有移动较矮的那边才可能增大容量
```

**时间复杂度：** O(n) - 只遍历一次数组
**空间复杂度：** O(1) - 只使用常数个变量

## 代码实现（TypeScript）

```typescript
function maxArea(height: number[]): number {
    // 左指针从数组开头开始
    let left = 0;
    // 右指针从数组末尾开始
    let right = height.length - 1;
    // 记录最大容量
    let maxArea = 0;

    // 当左右指针没有相遇时，继续循环
    while (left < right) {
        // 计算当前容量
        // 容量 = 较矮边的高度 * 两条线之间的距离
        const width = right - left;  // 宽度
        const minHeight = Math.min(height[left], height[right]);  // 高度（取较小值）
        const currentArea = width * minHeight;  // 当前容量

        // 更新最大容量
        maxArea = Math.max(maxArea, currentArea);

        // 移动指针：移动较矮的那一边
        // 原理：只有移动较矮的边，才有可能找到更高的边，从而增大容量
        if (height[left] < height[right]) {
            // 左边更矮，移动左指针
            left++;
        } else {
            // 右边更矮或相等，移动右指针
            right--;
        }
    }

    return maxArea;
}
```

## 代码原理详解

### 核心逻辑

1. **双指针初始化**：
   - `left = 0`：从最左边开始
   - `right = height.length - 1`：从最右边开始
   - 初始时宽度最大

2. **容量计算**：
   - 宽度 = `right - left`（两条线之间的距离）
   - 高度 = `Math.min(height[left], height[right])`（取较矮的边）
   - 容量 = 宽度 × 高度

3. **指针移动策略**：
   - 如果 `height[left] < height[right]`：移动 left++
   - 否则：移动 right--
   - 核心思想：移动较矮的边，才有可能增大容量

4. **终止条件**：
   - 当 `left >= right` 时停止，此时所有可能的组合都已考虑

### 设计思路

- **贪心思想**：每次移动都选择有可能增大容量的方向
- **双指针收缩**：从两端向中间收缩，逐步缩小搜索空间
- **木桶原理**：容量由较矮的边决定

## 常见问题

**Q1: 为什么一定要移动较矮的那边？**
A: 因为容量由较矮的边决定。移动较高的边，宽度减小，高度不会增加（受限于矮边），容量一定变小。只有移动较矮的边，才有机会遇到更高的边，增大容量。

**Q2: 如果两边高度相等，移动哪边？**
A: 移动哪边都可以，因为此时瓶颈在两边，移动任意一边都有可能改善。代码中选择移动 right，也可以移动 left。

**Q3: 这个算法会遗漏最优解吗？**
A: 不会。虽然我们每次只移动一边，但可以证明：任何被跳过的组合，其容量都不会大于我们已经计算过的某个组合。

**Q4: 能否用暴力法？**
A: 可以，但时间复杂度 O(n²)，数据量大时会超时。双指针法是最优解。

## 算法正确性证明

**反证法证明：移动较矮边的策略不会遗漏最优解**

假设：
- 当前状态：`left = i, right = j, height[i] < height[j]`
- 我们的策略：移动 `left++`
- 被跳过的组合：`(i, j-1), (i, j-2), ..., (i, i+1)`

证明这些被跳过的组合都不可能是最优解：

```
对于任意被跳过的组合 (i, k)，其中 i < k < j:

容量(i, k) = min(height[i], height[k]) * (k - i)
容量(i, j) = min(height[i], height[j]) * (j - i) = height[i] * (j - i)

因为 height[i] < height[j]，所以:
  min(height[i], height[k]) <= height[i]
  (k - i) < (j - i)

所以:
  容量(i, k) <= height[i] * (k - i) < height[i] * (j - i) = 容量(i, j)

即: 容量(i, k) < 容量(i, j)

所以如果 (i, j) 不是最优解，那么 (i, k) 也一定不是最优解。
```

因此，移动较矮边的策略不会遗漏最优解。
